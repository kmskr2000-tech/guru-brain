# 백테스트 v0.4 판단 공통 지침 (판단 에이전트용)

작업 디렉터리: /home/hatch/workspace/goals/50/guru-brain (git 레포). 너는 판단 담당이다. 파일만 쓰고 git 명령은 쓰지 않는다. 커밋·push 금지.

## 절대 읽지 않는 것 (위반 시 백테스트 무효)
- synthesis/backtests/v0.4/keys/ 디렉터리, keys.sha256, nonevent-check.md
- PREREG.md, execution-input.md, 다른 케이스의 패킷·판단 파일, 기타 결과·채점 문서
- 웹 검색·웹 접근 금지. 도구는 Read와 Write만 쓴다. 조건별로 허용된 파일 외에는 읽지 않는다.

## 입력
- 판단 입력은 지정된 패킷 파일 하나뿐이다. 패킷에 없는 사건 정보를 학습 지식으로 끌어와 입력 사실처럼 쓰지 않는다. 근거란에는 패킷에 있는 사실만 인용한다. 패킷에 없는 후속 전개를 아는 척 쓰지 않는다.

## 출력: 3회 반복
- 지정 경로 synthesis/backtests/v0.4/judgments/<case_id>/<condition>/run1.md, run2.md, run3.md 를 쓴다.
- 각 run은 패킷과 조건 문서만 보고 처음부터 독립적으로 판단한다. 앞 run의 판단을 복사하거나 의도적으로 바꾸지 않는다. 같은 입력이면 같은 결론이 나와도 괜찮고, 달라지면 달라진 대로 쓴다.

## 파일 형식 (모든 조건 공통)
```
---
case_id: <id>
type: <전환점 | 고평가 점검 | 무사건 | 홀드아웃>
condition: <조건명>
run: <1|2|3>
version_tested: <조건별 값>
prereg: "[[backtests/v0.4/PREREG]]"
model: claude-sonnet-5-5
temp: "세션 기본 (0.3 미강제)"
---

# 케이스 <id> — <condition> run<N>

## 입력 (익명화 수준: <패킷 frontmatter의 anonymization 값>)
- 패킷 파일: synthesis/backtests/v0.4/packets/<id>.md (요약 1~3줄, 결과 서술 금지)

## 발동 규칙 (판단 전에 먼저 명시)
- 발동 CR-NN: <v04·v03 조건은 CR 번호와 이유 한 줄씩. 렌즈·nolens는 "해당 없음(CR 미사용)">

## 판단
- 판단: <3~6문장. 위험 인식·국면 분류·점검 결론>
- 근거: <패킷의 사실과 조건 문서의 항목 인용. 철학 문서가 있는 조건은 노트 항목·신뢰 표식 인용>
- 확신도: <0~1 사이 숫자 하나. "판단 시점 후 60영업일 안에 아래 무효화 조건이 발동하지 않는다"일 확률>
- 무효화 조건 (1~3개, 필수):
  1. <검증 가능한 지표 + 숫자 문턱 + 방향. 예: "원/달러 환율이 1,300원을 넘으면 틀림">
  (각 조건은 60영업일 안에 외부 데이터로 판정 가능해야 한다. 지표명·문턱 숫자·기간을 적는다. 문턱이 비면 안 된다.)

## 베이스라인 답 3종
- 해당 없음 (판단 파일 단독 제출)

## 채점
- (비움. 채점 세션이 작성)

## 규칙 개정 제안
- <홀드아웃 케이스(KR-2018-11-01, KR-2016-06-01, KR-2026-07-01)는 반드시 비운다("(비움)"만). 비홀드아웃 케이스는 개정이 필요하다고 느낀 점을 기록만 한다. 규칙·페르소나 파일은 수정하지 않는다. 없으면 "없음". 렌즈·nolens 조건은 "해당 없음".>
```

## 금기 (엄수. 위반 시 판단 무효)
개별 종목 매수·매도 권유, 목표주가, 매매 타이밍("지금 사라/팔아라"류), 단기 주가 예측, 비중·현금 수치 지시를 쓰지 않는다. 종목이 토큰(종목A 등)이어도 토큰 단위 권유 금지. 점수(채점)는 쓰지 않는다.

## 기타
- 확신도는 0~1 척도(템플릿의 /100은 무시).
- 한국어로 쓴다.
- 문서가 길어도 조건에서 허용된 파일은 전부 읽는다(일부만 읽고 시작하지 말 것).
- 3개 run을 모두 쓴 뒤, 쓴 파일 경로 3개만 한 줄씩 보고한다.
